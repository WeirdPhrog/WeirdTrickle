## Назначение

WeirdTrickle — форк [MagiTrickle](https://github.com/MagiTrickle/MagiTrickle), утилиты для точечной маршрутизации сетевого трафика по заданным доменным именам, IP-адресам и подсетям. Представляет собой установочный пакет, устанавливаемый в дополнение к операционной системе маршрутизатора.

<p align="center">
  <img src="img/main_screenshot.png" alt="Скриншот исходного MagiTrickle"/>
</p>

Скриншот исходного проекта; новые настройки этого форка на нём не показаны.

WeirdTrickle обрабатывает DNS-запросы через промежуточный компонент перед основным DNS-сервером роутера, кеширует ответы и сопоставляет IP-адреса с доменными именами. Доменные правила начинают работать после получения соответствующего DNS-ответа. После запуска или перезапуска сервиса может понадобиться новый DNS-запрос; очистка DNS-кэша клиента помогает получить его раньше. Правила для IP-адресов и подсетей от DNS-запросов не зависят. DNS, который клиент отправляет в обход этого компонента, например напрямую через DoH, не наполняет его кеш.

Это выборочная маршрутизация, а не общий запрет выхода в WAN: трафик без совпадения с действующими правилами обрабатывает сам роутер. Домены на одном IP нельзя надёжно развести по разным интерфейсам только по DNS. Срок динамической записи ограничен TTL с настроенной надбавкой; само наличие открытого соединения не продлевает этот срок. При смене VPN уже открытым соединениям может потребоваться переподключение из-за состояния NAT.

## Изменения относительно оригинала

Ниже перечислены изменения форка относительно [исходного MagiTrickle на коммите a058158](https://github.com/MagiTrickle/MagiTrickle/commit/a05815881e888a53f91f1da0e295ada9737ebb86), от которого он создан. Подробности настройки и установки приведены в следующих разделах.

### Маршрутизация

- **Groups имеют приоритет над Subscriptions** для IPv4 и IPv6: отдельный домен из группы может использовать другой VPN, даже если его IP входит в большую подсеть/ASN подписки.
- Приоритет сохраняется после обновления подписок, редактирования и переключения групп, перезапуска и повторного применения правил firewall.
- Обновление подписки сохраняет действующие наборы и маршруты остальных подписок. Новое содержимое ipset сначала полностью подготавливается, затем заменяет старое; ошибка заполнения не оставляет частично очищенный список. При переносе адресов между группами новые совпадения подготавливаются до удаления прежних.
- При смене интерфейса сохраняются маркировка и таблица маршрутизации. На время переключения действует блокирующий маршрут, чтобы пакеты не проваливались в системный WAN; краткая потеря пакетов при переключении возможна. Шлюз выбирается из маршрутов по умолчанию с учётом метрики, а не из случайного маршрута к отдельной подсети.
- Лимит ipset учитывает размер подписки и допускает больше 65 536 записей. Для безопасной замены списка временно нужны старый и новый наборы в памяти; при нехватке ресурсов возвращается ошибка, прежний список сохраняется.
- При маркировке пакета каждый ipset проверяется один раз вместо двух; цепочки несовпавших групп/подписок пропускаются. Направление ответа проверяется один раз перед обходом всех наборов. Порядок приоритетов и повторная проверка исходящих пакетов существующих соединений сохранены; это сокращение операций, а не обещание удвоения пропускной способности роутера.
- Исправлено восстановление маршрутов после переподключения VPN: удалённый маршрут создаётся заново и при прежнем шлюзе; учитывается пересоздание интерфейса с новым индексом.
- Исправлена синхронизация DNS-адресов в ipset: записи `/32` и `/128` корректно сопоставляются с данными ядра и не удаляются из-за различия представлений одного адреса.
- Статическое IP-правило сохраняет бессрочный срок действия при совпадении с DNS-адресом. После удаления статического правила оставшаяся динамическая запись снова получает конечный TTL.

### Загрузка подписок

- Добавлен **общий выбор интерфейса загрузки** на странице Subscriptions. Он применяется к предварительной загрузке URL, ручной синхронизации и обновлению по расписанию; сохраняется сразу и действует без перезапуска.
- Если выбранный интерфейс недоступен или загрузка через него завершилась ошибкой, выполняется повторная попытка через системный маршрут. Если обе попытки не удались, сохраняются текущие правила подписки.
- К выбранному интерфейсу привязаны HTTP-запросы, перенаправления и запросы к внешним DNS-серверам. Локальный DNS-прокси роутера использует свои настройки upstream.
- Добавлена обработка HTTP-перенаправлений **303, 307 и 308**, кроме ранее поддерживаемых 301 и 302.
- Загрузка подписок учитывает отмену запроса и остановку сервиса. Ошибка сохранения общего интерфейса возвращает его прежнее значение; выбранный, но временно отсутствующий VPN остаётся в настройке.
- После повторных ошибок загрузки пауза автоматических попыток увеличивается от 1 до 15 минут. Успешная загрузка сбрасывает паузу; ручная синхронизация не ждёт её окончания. Последние рабочие правила сохраняются.

### Производительность больших списков

- При обработке DNS перебираются только включённые доменные правила. IP-подсети из больших ASN больше не проверяются на совпадение с каждым доменным именем.
- Чтение настроек DNS не ждёт пересборки ipset. Во время обновления запросы к доменам вне действующих и добавляемых правил проходят без ожидания общего замка; для совпавших доменов ответ по-прежнему ждёт применения маршрутизации. В **1.0.1** исправлен пропуск новых доменов подписок в этом префильтре: ожидание учитывает как добавление подписки, так и обновление её правил.
- Массовое преобразование правил Groups и Subscriptions использует индекс по ID вместо повторного полного поиска каждой записи. Объём этой работы растёт линейно с размером списка; порядок записей и ID существующих правил сохраняются.
- Пересекающиеся CNAME-правила одной группы больше не вызывают повторное добавление тех же адресов в ipset в рамках обработки одной CNAME-записи.
- Исправлены сортировка и восстановление порядка очень больших групп в веб-интерфейсе: они больше не упираются в ограничение JavaScript на количество аргументов функции.

### DNS и время жизни адресов

- Domain, Namespace и Wildcard сопоставляются без учёта регистра; имена в DNS-кэше также нормализуются.
- Исправлена обработка нулевого, дробного остаточного и чрезмерно большого TTL: динамические записи не становятся бессрочными из-за округления до нуля или переполнения.
- Повторный DNS-ответ с коротким TTL не сокращает срок маршрутизации адреса, выданного ранее с более длинным TTL, в том числе при совпадении IP у нескольких доменов одной группы.
- Обрабатываются IP-подсказки и несколько целей HTTPS/SVCB, а также адреса в дополнительной секции DNS-ответа. CNAME-связи учитываются независимо от порядка записей в ответе. При включённой фильтрации AAAA удаляются и IPv6-подсказки HTTPS/SVCB.
- Если DNS-адрес не удалось добавить в нужный ipset, клиент получает `SERVFAIL` без адресов вместо успешного ответа, по которому трафик мог бы обойти правило. Сопоставление домена и добавление адреса защищены от одновременного редактирования группы.
- Незавершённое отключение одной группы не вызывает `SERVFAIL` для посторонних доменов и не приводит к падению при последующем событии сетевого интерфейса.
- Просроченные CNAME-связи перестают участвовать в сопоставлении сразу после истечения срока, ещё до очередной очистки кэша.
- DNS-прокси проверяет минимальную длину заголовка, признак ответа и ID запроса. Запоздавшие UDP-ответы с чужим ID отбрасываются без продления таймаута. Если TCP-ответ не проходит эти проверки, соединение закрывается.
- Исправлены гонки при чтении и обновлении DNS-кэша и при закрытии пула DNS-соединений.
- IPv6-адреса и подсети в журнале выводятся в корректном формате.

### Настройки, редактирование и надёжность

- Конфигурация записывается через временный файл с последующей атомарной заменой. Если исходный конфиг не удалось прочитать, приложение сообщает об ошибке и не перезаписывает его.
- Версия формата конфигурации отделена от версии выпуска приложения; сохранена совместимость с конфигурациями оригинала и ранних выпусков форка.
- При редактировании группы корректно применяются смена интерфейса и включение/отключение. Изменённые регулярные выражения компилируются заново вместо использования прежнего шаблона.
- Перед массовой заменой групп проверяются отсутствующие объекты и повторяющиеся ID; при ошибке применения выполняется откат к предыдущим группам.
- При сохранении настроек и применении правил API сообщает об ошибках записи конфигурации и синхронизации ipset.
- Если правила уже применены, но запись конфига не удалась, API прямо сообщает, что изменения действуют и не сохранены на диск.
- Исправлены гонки между редактированием правил, DNS-обработкой, сохранением настроек и применением iptables.
- Если параллельный запрос уже изменил группу после чтения её API-обработчиком, редактирование отдельной группы или её правил возвращает `409 Conflict`, вместо потери чужого изменения. Запрос можно повторить после перечитывания группы. Это не контроль версий давно открытой вкладки, отправляющей целиком список групп или подписок.
- Улучшена очистка ресурсов и firewall при неудачном запуске и остановке сервиса; исправлено падение при остановке с отключённым HTTP-интерфейсом.
- Веб-интерфейс проверяет правила и на скрытых страницах списка, а предупреждение о несохранённых изменениях работает даже при ошибках в правилах. Некорректные IPv4/IPv6-адреса и префиксы больше не считаются корректными подсетями.
- Выключенные некорректные правила не блокируют сохранение Groups; при включении правило проверяется снова. Результат проверки неизменённого шаблона переиспользуется, поэтому каждый ввод не компилирует заново все регулярные выражения списка.
- Закрытие диалога добавления подписки отменяет загрузку; запоздавший ответ не меняет новый диалог. Импорт использует текущий выбранный тип правила, даже если предпросмотр ещё пересчитывается.
- Повреждённое или недоступное хранилище браузера больше не мешает запуску WebUI; сохранённый токен авторизации продолжает работать после перезагрузки страницы.

### Безопасность API и обработка данных

- HTTP API отклоняет браузерные запросы с посторонним `Origin` / `Sec-Fetch-Site: cross-site`, в том числе при отключённой авторизации. Встраивание WebUI в страницу другого сайта запрещено; локальные CLI-запросы без этих заголовков поддерживаются.
- Ограничены размер JSON-запроса (32 МиБ), тела запроса входа (8 КиБ), логина (256 байт) и пароля (1024 байта). JSON должен содержать ровно одно значение; HTTP-сервер ограничивает время чтения заголовков и тела.
- Размер скачанного списка подписки ограничен 16 МиБ **после распаковки HTTP gzip**. Превышение лимита считается ошибкой загрузки и не заменяет действующие правила частичным списком.
- Для сопоставления регулярных выражений задан таймаут 100 мс с периодической проверкой библиотекой. Шаблон с чрезмерным перебором не блокирует DNS-обработку бесконечно; при таймауте совпадение не засчитывается.
- Сборка переведена на Go 1.26.9, обновлены зависимости Go и frontend с известными исправлениями безопасности. CI запускает `govulncheck` и `npm audit` перед выпуском. Frontend собирается и тестируется с одним набором зависимостей из `package-lock.json`; Deno не переустанавливает их отдельно.

Проверка источника браузерного запроса не заменяет авторизацию: при отключённой авторизации прямой доступ к API из доступной ему сети по-прежнему позволяет управлять настройками.

При размещении WebUI за обратным прокси сохраняйте исходный `Host` браузерного запроса (для nginx: `proxy_set_header Host $http_host;`). Произвольный `X-Forwarded-Host` не считается доверенным источником и не отключает проверку `Origin`.

### Установка, обновления и проверки

- Добавлена установка и переход с оригинала **одной командой** для Entware, Keenetic и Netcraze с автоматическим выбором архитектуры и варианта `_kn`.
- Обновления берутся из этого форка через `weirdtrickle-update`; доступны проверка версии (`--check`) и установка конкретного выпуска (`--version`).
- Перед заменой пакета создаётся резервная копия, существующий конфиг сохраняется. Пакет помечается `hold`, чтобы обычный `opkg upgrade` не заменил его оригиналом.
- Установщик отличает WeirdTrickle от оригинального пакета по полю `Description`: даже при одинаковом номере версии переход с оригинала выполняет переустановку с сохранением настроек.
- Установщик проверяет SHA-256 пакета, блокирует одновременные обновления и требует явного выбора версии для понижения. Пакет и его контрольная сумма скачиваются из одного фиксированного релиза.
- Блокировка установщика находится в `/tmp`: после перезагрузки роутера прерванное обновление не оставляет постоянный запрет на следующую установку.
- При удалении пакета Entware удаляется и созданный установщиком файл архитектуры `magitrickle-fork.conf`; при обновлении пакета он сохраняется.
- Релиз публикуется только после успешных проверок и сборки всех семи вариантов Entware. Повторный запуск публикации не заменяет файлы уже опубликованного выпуска.
- Добавлены регрессионные тесты приоритетов Groups/Subscriptions, TTL, восстановления маршрутов, загрузки через выбранный интерфейс и сохранения конфигурации, а также замеры больших списков. CI проверяет гонки, IPv4/IPv6-пакеты через LAN и FORWARD на iptables legacy/nft, отсутствие выхода в WAN во время обновлений и при недоступном VPN, ipset на 65 537 адресов, DNS HTTPS/SVCB и отказ записи в ipset, установщик и браузерные сценарии. Проверки в CI выполняются на Linux; замеры производительности относятся к тестовому серверу.

## Интерфейс загрузки подписок

На странице **Subscriptions / Подписки**, над списком, находится общий выбор **«Интерфейс загрузки»**. Он применяется сразу ко всем подпискам: к загрузке нового URL, ручной синхронизации и обновлению по расписанию. Выбор автоматически сохраняется в `app.subscriptionFetchInterface` в `config.yaml`, действует без перезапуска и сохраняется после обновления приложения. В старых конфигурациях используется системный маршрут.

При выборе VPN сначала весь запрос, включая HTTP-перенаправления, выполняется через этот интерфейс. Если интерфейс отсутствует, отключён или загрузка завершается ошибкой, исходный URL повторно загружается через системный маршрут. Каждой попытке отводится до 15 секунд. Если обе попытки не удались, текущие правила подписки остаются на месте. Возврат к VPN проверяется при следующей загрузке; выбранное значение не сбрасывается.

Запросы к внешнему DNS-серверу также привязаны к интерфейсу. Если системный DNS указывает на сам роутер (например, `127.0.0.1`), запрос передаётся локальному DNS-прокси, который использует собственные настройки upstream. Публичный DNS-сервер автоматически не подставляется. Интерфейс должен иметь рабочую маршрутизацию к источнику подписки.

Поле интерфейса внутри каждой подписки по-прежнему управляет маршрутизацией трафика по её правилам; общий интерфейс загрузки на него не влияет. Это также не меняет приоритет Groups и поведение их VPN. Настройка применяется только к загрузке списков подписок: установщик и `weirdtrickle-update` используют системную маршрутизацию.

## Установка из этого форка: Keenetic / Netcraze / Entware

На официальной KeeneticOS/NetcrazeOS сначала должен быть установлен **Entware**. Команда выполняется от root в его Linux-оболочке (обычно SSH-порт 222), а не в командной строке Keenetic/Netcraze на порту 22. Архитектура пакета определяется автоматически через `opkg`; для Keenetic/Netcraze выбирается вариант `_kn`, если он предусмотрен для этой архитектуры.

Первая установка, переход с оригинального MagiTrickle или обновление уже установленного форка одной командой:

```sh
opkg update && opkg install curl ca-bundle coreutils-sha256sum && curl -fsSL https://github.com/WeirdPhrog/WeirdTrickle/releases/latest/download/install.sh -o /tmp/weirdtrickle-install.sh && sh /tmp/weirdtrickle-install.sh
```

Команда сначала устанавливает инструменты HTTPS-загрузки и проверки SHA-256. Установщик скачивает пакет только из [релизов WeirdPhrog/WeirdTrickle](https://github.com/WeirdPhrog/WeirdTrickle/releases), проверяет SHA-256, устанавливает зависимости приложения через Entware и перезапускает сервис.

**Перед переходом с оригинала удалять MagiTrickle не нужно.** Если в веб-интерфейсе есть несохранённые изменения, сначала нажмите **«Сохранить изменения»**. Установщик сохраняет существующий `/opt/var/lib/magitrickle/config.yaml`; перед заменой пакета создаёт архив состояния и настроек в `/opt/var/backups/magitrickle/`. Настройки Groups и Subscriptions повторно вводить не нужно. После обновления перезагрузите страницу веб-интерфейса.

Веб-интерфейс при настройках по умолчанию: `http://IP_РОУТЕРА:8080`. При обновлении адрес/порт остаются из вашей конфигурации.

**Переход с версий `2026.x.x.x` на WeirdTrickle 1.x:** один раз выполните полную команду установки выше. Старый установленный `magitrickle-update` не распознаёт трёхкомпонентный номер версии и сообщает `Invalid release version`. Новый установщик разрешает этот переход с сохранением конфига. Имя пакета `magitrickle`, сервис `S99magitrickle` и пути настроек сохраняются для совместимости; вручную переносить или удалять их не нужно.

### Дальнейшие обновления

```sh
weirdtrickle-update --check    # только проверить доступную версию
weirdtrickle-update            # установить последний готовый релиз этого форка
```

Используется установленная команда `/opt/bin/weirdtrickle-update`; прежняя `magitrickle-update` сохранена как совместимый псевдоним. В оригинальной версии этих команд может не быть — тогда используйте полную команду установки выше. Пакет помечается `hold`, чтобы обычный `opkg upgrade` не заменил его оригиналом. Обновлять WeirdTrickle следует именно этой командой; она снимает hold на время установки и возвращает его после неё. Другие пакеты обновляются штатно. Фоновое автоматическое обновление приложения на роутере не включается; обновление списков подписок по расписанию продолжает работать.

Для возврата к конкретному опубликованному релизу:

```sh
weirdtrickle-update --version 1.0.0
```

Версия указывается без `v` и без пакетной ревизии `-1`: для тега `v1.0.0` — `1.0.0`. Автоматическое понижение обычной версии запрещено; явный `--version` разрешает его, в том числе возврат к старому календарному выпуску. Переход с `2026.x.x.x` на новую схему обработан установщиком отдельно. Конфигурация сохраняется и при понижении версии; её восстановление из архива выполняется отдельно при необходимости. Удаление пакета: `opkg flag ok magitrickle && opkg remove magitrickle`.

### Сборка будущих релизов

При push в `develop` [GitHub Actions](https://github.com/WeirdPhrog/WeirdTrickle/actions/workflows/build.yml) запускает:

- тесты backend с race detector, `go vet` и проверку форматирования;
- проверку известных уязвимостей зависимостей через `govulncheck` и `npm audit`;
- замеры обработки больших списков правил и проверки восстановления IPv4/IPv6-маршрутов после пересоздания интерфейса;
- проверку реальных IPv4/IPv6-пакетов на iptables legacy/nft в отдельных Linux network namespaces;
- проверку загрузки подписок через выбранный интерфейс, включая DNS и переход на системный маршрут;
- тесты установщика и ShellCheck;
- проверку и сборку веб-интерфейса, модульные тесты Deno и браузерные тесты Playwright.

После проверок собираются семь вариантов Entware. Обычные push и pull request проверяются и собираются без публикации релиза.

Номер хранится в файле `VERSION` в формате `MAJOR.MINOR.PATCH`: `1.0.1` для совместимых исправлений, `1.1.0` для новых совместимых возможностей, `2.0.0` для несовместимых изменений API или конфигурации. Версии увеличиваются осмысленно, независимо от даты и номера запуска CI.

Для выпуска измените `VERSION`, закоммитьте изменения и отправьте соответствующий тег, например `git tag v1.0.1 && git push origin v1.0.1`. CI проверяет совпадение тега с файлом. Только тег запускает публикацию: после успеха всех проверок и семи сборок создаётся релиз с пакетами, `VERSION`, `SHA256SUMS` и установщиком. Номер в WebUI и версия пакета берутся из того же файла; суффикс `-1` в opkg — ревизия упаковки. Уже опубликованные файлы не перезаписываются. Достаточно встроенного `GITHUB_TOKEN`; собственные токены не нужны.

Эти проверки выполняются в CI на Linux и не заменяют проверку установки и работы на конкретной модели роутера.

## OpenWrt

Исходная поддержка OpenWrt сохранена в коде и Makefile. Для сборки его пакетов запустите workflow вручную из ветки `develop` с `platforms: all`; вместе с Entware будут собираться `.ipk` и `.apk` для конфигураций `config/openwrt`. Обычные автоматические проверки и релизы охватывают только сборки Entware. Установщик выше предназначен для Entware. APK в сборках OpenWrt подписан одноразовым ключом сборки и не подключён к доверенному пакетному репозиторию OpenWrt; для штатного распространения APK нужен собственный постоянный ключ и feed.

## Описание типов правил

Доменные правила сопоставляются без учёта регистра. Для обычного домена со всеми поддоменами используйте **Namespace**, для одного точного имени — **Domain**.

### Namespace (Именное пространство)

Охватывает указанный домен и все его поддомены.

Например, при записи `example.com` будут обрабатываться:

```
✅ example.com
✅ sub.example.com
✅ sub.sub.example.com
❌ anotherexample.com
❌ example.net
```

### Wildcard (Подстановочный шаблон)

Используется [go-wildcard v2.1.0](https://github.com/IGLOU-EU/go-wildcard/tree/v2.1.0) со следующими операторами для ASCII-доменов:

- `*` — ноль или больше любых символов;
- `?` — ноль или один любой символ;
- `.` — ровно один любой символ, включая точку.

Точка в Wildcard не означает строго разделитель доменных уровней: `*example.com` совпадёт также со строкой `exampleXcom`. Если требуется буквальная точка, используйте Namespace/Domain либо RegExp с `\.`.

Например, при записи `*example.com` будут обрабатываться:

```
✅ example.com
✅ sub.example.com
✅ sub.sub.example.com
✅ anotherexample.com
❌ example.net
```

### Domain (Точный домен)

Правило применяется только к строго указанному домену, без поддоменов.

Например, при записи `sub.example.com` будут обрабатываться:

```
❌ example.com
✅ sub.example.com
❌ sub.sub.example.com
❌ anotherexample.com
❌ example.net
```

### RegExp (Регулярное выражение)

Для опытных пользователей. Используется парсер [dlclark/regexp2](https://github.com/dlclark/regexp2). Без якорей выражение может совпадать с частью имени; для полного совпадения используйте `^` и `$`.

Например, при записи `^[a-z]*example\.com$` будут обрабатываться:

```
✅ example.com
❌ sub.example.com
❌ sub.sub.example.com
✅ anotherexample.com
❌ example.net
```

### Subnet / Subnet6 (IP-адрес или подсеть)

Правила IPv4 (`subnet`) и IPv6 (`subnet6`) задаются адресом или сетью в формате CIDR. Например: `192.0.2.10`, `192.0.2.0/24`, `2001:db8::10`, `2001:db8::/32`. Они применяются без предварительного DNS-запроса. Для маршрутизации ASN в подписке нужен список его IP-подсетей; само имя вида `AS12345` не преобразуется в подсети автоматически.
